# 会員登録・ログインとアプリ全体の説明

添付の開発ガイドに合わせ，既存のFlet版サブマネへ会員登録・ログイン・ログアウトを追加しました．**画面はAndroidアプリ側，正式な認証と永続保存は別開発のAPIサーバ側**という構成です．この一式には会員画面，共通通信クライアント，API未接続で操作を試すダミー実装が含まれます．

## 1．まず動かす

ZIPを新しいフォルダへ展開し，`pyproject.toml` が見える `submane-flet` フォルダを開きます．エクスプローラーのアドレスバーに `cmd` と入力すると，その場所でコマンドプロンプトが開きます．Python 3.12の環境で次を実行してください．

```bat
python -m pip install -e ".[dev]"
flet run
```

`Downloads does not appear to be a Python project` と表示される場合は，実行しているフォルダに `pyproject.toml` がありません．ZIPを展開したプロジェクトフォルダへ移動してください．仮想環境の作成方法は一式の `README.md` に記載しています．

起動したら次の順で試せます．

1. 「会員登録」を選びます．
2. メールアドレス，パスワード，確認用パスワードを入力します．
3. 「会員登録する」を押すと，完了メッセージとログインフォームが表示されます．メールアドレスだけを引き継ぎます．
4. 同じパスワードを入力して「ログイン」を押すと，ホームへ進みます．
5. ヘッダーの「追加」からサブスクを登録します．
6. ヘッダーのアカウントアイコンから，ログイン中のメールと「ログアウト」を確認できます．

初期設定は試用モードです．メールは送信しません．アカウントとサブスク情報は，同じアプリセッション内だけで保持します．ログアウト後に同じユーザでログインすると自分の一覧が戻りますが，アプリを終了・再起動すると再登録が必要です．ブラウザ版を新しいセッションで開いた場合や別端末からアクセスした場合も，試用データは共有しません．

## 2．ファイルごとの役割

| ファイル | 担当すること |
|---|---|
| `src/views/account.py` | 登録・ログインのフォーム切り替え，入力エラー，進行表示，ログイン中のアカウント表示，ログアウト |
| `src/auth_validation.py` | メール形式，パスワードの長さ，確認用パスワードの一致の検証 |
| `src/api_client.py` | `sign_up()`，`log_in()`，`log_out()`，HTTP通信，応答の検証，ユーザとトークンの管理 |
| `src/dummy_data.py` | 試用アカウント，パスワードハッシュ，ユーザごとのサブスク情報，名称検索用マスタ |
| `src/app_context.py` | 画面で共有するAPIクライアント，遷移関数，ログイン状態，二重送信を防ぐ状態 |
| `src/main.py` | 起動，共通ヘッダー・タブ，画面切り替え，未ログイン時のアクセス制限 |
| `src/config.py` | 試用モードの切り替え，API URL，通信タイムアウト |
| `src/theme.py` | 共通の色，フォント，余白，入力欄，ボタン |

`account_view(page)` は画面の中身の `ft.Control` を返します．ヘッダーとタブは `main.py` が付けます．画面から `httpx` を直接呼ばず，すべて `context.api` を通します．既存のサブスク登録・ホーム・詳細も同じクライアントを使うので，ログインしたユーザの認証情報で要求できます．

## 3．登録とログインで何が起こるか

**会員登録**では，入力を検証した後，`context.api.sign_up(email, password)` を呼びます．成功するとパスワード欄を消し，メールアドレスを引き継いでログインモードに戻ります．会員登録だけではログイン済みにしません．重複登録や通信エラーでは成功メッセージを表示しません．

**ログイン**では，`context.api.log_in(email, password)` を呼びます．正式API版では，HTTP成功に加えて，有効な形式のBearerトークンとユーザのID・メールがそろっていることを確認します．検証に成功した場合だけ `context.logged_in = True` にして，`context.navigate("/home")` を呼びます．返却情報が不足している場合はホームへ進みません．

**ログアウト**では，端末内のトークンとユーザ情報を直ちに破棄します．API版では対象トークンを使ってサーバへも通知します．通知に失敗した場合も端末はログアウトし，その旨を画面に表示します．サーバでのトークン失効はAPIの担当です．

`main.py` はヘッダー，タブ，URL変更，Androidの戻る操作で遷移するときにログイン状態を確認します．未ログインならアカウント画面へ戻します．APIでトークン失効の401を受けた場合は認証状態を消し，次の遷移で再ログインを求めます．

処理中はフォームを操作できず，同じボタンを続けて押しても要求を重ねません．画面が作り直された後に古いログイン応答が届いても，ログイン状態を復活させません．

## 4．入力とパスワードの扱い

登録ポリシーは正式仕様に長さがなかったため，暫定で次のようにしています．API側と方針を決めたら `auth_validation.py` を合わせてください．

| 項目 | 現在の扱い |
|---|---|
| メール | 基本的なASCIIメール形式，254文字まで．前後空白を除き，大文字小文字を区別しない |
| 新規登録のパスワード | 15〜128文字．確認欄との一致が必要 |
| ログインのパスワード | 空欄を拒否し，128文字まで．既存アカウントを考慮して登録時の最小長を強制しない |
| 使用できる文字 | 日本語や空白も許可．英大文字・数字・記号の必須条件は設けない |
| パスワードの変更 | 前後空白を削除せず，長すぎる値を切り詰めない |
| 画面上の扱い | 伏字と表示切り替え．登録・ログイン成功，モード変更，通信・認証エラーで入力欄を消す |
| 保存 | パスワードやトークンをファイルへ書かない．自動ログインは行わない |

試用ストアはユーザ別のランダムsaltを使い，PBKDF2-HMAC-SHA256を600,000回反復したハッシュで照合します．ハッシュ計算は別スレッドで行います．平文パスワードは試用ストアのレコードに保存しません．正式API版はHTTPSで認証情報を送り，サーバ側が適切にハッシュを保存します．

このパスワードは「サブマネのアカウント用」です．Netflix等の外部サービスのパスワードをサブスク登録情報や退会メモに保存する機能はありません．

## 5．正式APIへの接続

仕様どおり，APIサーバとDBはこのプロジェクトの外で開発します．次のルートと返却形式は**接続例としての仮契約**です．確定したサーバ仕様に合わせて `api_client.py` のルート・応答変換・認証ヘッダーを修正してください．

| 関数 | 仮ルート | リクエスト | 成功時の返却 |
|---|---|---|---|
| `sign_up(email, password)` | `POST /auth/signup` | `email`，`password` | 201，`{"user": {"id": "...", "email": "..."}}` |
| `log_in(email, password)` | `POST /auth/login` | `email`，`password` | 200，`access_token`，任意の `token_type: "bearer"`，`user` |
| `log_out()` | `POST /auth/logout` | Authorizationヘッダー | 204で空の本文，または200でJSON |
| `list_subscriptions()` | `GET /subscriptions` | Authorizationヘッダー | ログインしたユーザのサブスク配列 |
| `get_subscription(id)` | `GET /subscriptions/{id}` | Authorizationヘッダー | 同じユーザが所有する1件 |
| `create_subscription(data)` | `POST /subscriptions` | サブスク情報とAuthorizationヘッダー | 保存した1件，`id` を含む |

ログイン成功の返却例です．値は説明用の架空データです．

```json
{
  "access_token": "sample-token",
  "token_type": "bearer",
  "user": {
    "id": "user-1",
    "email": "tester@example.com"
  }
}
```

以後の認証付き要求は `Authorization: Bearer <取得したトークン>` を使います．サブスク要求に自己申告のユーザIDを追加して所有者を切り替える構成にはしていません．API側はトークンからユーザを確定し，一覧・詳細・保存の所有者を検証してください．アプリの画面制限とサーバのアクセス制御の両方が必要です．

設定例は次のとおりです．

```python
# src/config.py
USE_DUMMY_DATA = False
```

```bat
set SUBMANE_API_BASE_URL=https://実際のAPIのURL/api
flet run
```

`SUBMANE_API_TOKEN` による自動ログインは使用しません．会員画面から認証してください．通信失敗時に試用ストアへ切り替えて成功扱いにする処理もありません．

メール確認，パスワード再設定，端末へのトークン永続化，トークン更新は今回の実装に含めていません．正式APIがメール確認後の有効化を要求する場合は，現在の「登録完了→ログイン」の表示もその仕様に合わせて変更します．

## 6．チームの実装へ組み込む

今回の一式は既存リポジトリの提供がない状態で作った，単独で動くプロジェクトです．更新された `account.py` だけを以前の一式へコピーすると，認証関数や共有状態が不足します．**まず更新版ZIPを別フォルダに展開して全体で起動**してください．

実際のチームリポジトリには，会員画面担当とAPI担当と確認して統合します．主な対象は `views/account.py`，`auth_validation.py`，`api_client.py`，`dummy_data.py`，`app_context.py`，`main.py`，`pyproject.toml` です．既存担当者の処理がある場合は必要部分を取り込んでください．

固定しているFlet 1.0.3では，入力欄のエラーは `TextField.error`，画面遷移は `await page.push_route(...)` を使います．既存のサブスク登録画面のエラー表示も同じプロパティへ合わせました．

## 7．検証結果

```bat
python -m pytest -q
```

**59件成功**しました．入力検証，試用の重複登録と認証失敗，ユーザ別データ，ログアウト後のアクセス制限，仮APIの要求・応答，204ログアウト，不正な認証応答，通信エラー，二重送信，遅れて届く応答の無効化，既存のサブスク登録・ホーム反映を確認しています．

画面のテストは実際のFletコントロールを構築してPython側のイベントを実行するもので，FlutterやAndroid実機の画面描画を検証したものではありません．正式APIとの接続，APKビルド，2端末同期も未確認です．実機では会員登録・ログイン・ログアウトに加え，キーボード表示，長いエラー文，パスワード表示切り替え，戻る操作を確認してください．
