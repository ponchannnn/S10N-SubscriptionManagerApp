# サブマネ 開発ガイド(チームE1)

複数のサブスクリプションを一元管理し、支払期日と費用の見える化、解約・再契約のしやすさによって、解約忘れや無駄な出費を防ぐAndroidアプリです。
このファイルは、5人が同じ前提で開発を進めるための取り決めをまとめたものです。内容を変えるときはチームに共有してから更新してください。

> **このガイドの前提(提案です。合わなければ直してください)**
> - このリポジトリで作るのは Androidアプリだけ。Python の Flet で作る(PythonだけでUIを書き、APKにビルドできるフレームワーク)
> - API(サーバとDB)は別で作る。このリポジトリには含めず、アプリはAPIを呼び出す側になる
> - フレームワークやファイル名など、文書に書かれていなかった部分はこちらで仮決めしています。「要確認」「要調査」と書いた項目は特に確認が必要です

---

## 2. セットアップ

```bash
git clone <リポジトリURL>
cd submane

# 仮想環境
python3 -m venv .venv
source .venv/bin/activate        # Windows は .venv\Scripts\activate

# pyproject.toml の dependencies / dependency-groups.dev と同じバージョンを入れる
pip install flet==1.0.3 flet-charts==1.0.3 httpx==0.28.1 \
            flet-cli==1.0.3 flet-desktop==1.0.3 flet-web==1.0.3 pytest
```

Python 3.12以上であれば動作します(3.14でも動作確認済み)。

### アプリを動かす

```bash
# PC上のウィンドウで確認(コードを保存すると自動で反映される)
flet run

# ブラウザで確認したい場合
flet run --web

# Androidの実機で確認(スマホに「Flet」アプリを入れ、表示されるQRコードを読む)
flet run --android
```

普段の開発は `flet run` で十分です。ウィンドウ幅は390pxを基準にします。

### APIとのつなぎ方

`src/config.py` の2つの設定で切り替えます。

```python
USE_DUMMY_DATA = True                 # True の間はAPIを呼ばず、ダミーデータで動く
API_BASE_URL = "https://<APIのURL>"   # APIができたら設定する
```

APIができるまでは `USE_DUMMY_DATA = True` のまま画面を作り、APIが使えるようになった機能から順に切り替えます。

### APKを作る

```bash
flet build apk
# できたAPKを実機に入れる
adb install build/apk/<ファイル名>.apk
```

APKのビルドには Flutter SDK、Android SDK、JDK が必要で、準備に時間がかかります。全員がそろえる必要はないので、ビルド担当を1人決めるのがおすすめです(要確認)。

**注意(要調査)**: ビルドしたAPKから `http://` のURLへは、Androidの初期設定では通信できません。APIが `https://` で公開されるかをAPI担当に確認してください。

### 画面ファイルの書き方

各画面は「`page` を受け取って、その画面の中身を返す関数」を1つ持つ形にそろえます。

```python
# src/views/breakdown.py
import flet as ft
import theme


def breakdown_view(page: ft.Page) -> ft.Control:
    """内訳画面の中身を返す。"""
    return ft.Column(
        controls=[
            ft.Text("今月の支払い見込み", size=26, weight=ft.FontWeight.BOLD, color=theme.INK),
            # ここに円グラフと金額一覧を置く
        ],
    )
```

ヘッダーと下部タブは `main.py` が全画面に付けるので、各画面では中身だけを作ります。

### ホーム画面について

先に作ったHTML版(`docs/home_mock.html`)は、Fletではそのまま使えません。見た目と動きの見本として残し、`views/home.py` に作り直します(担当: 玉造)。作り直すときに引き継ぐ仕様は次のとおりです。

- 4列のアイコン一覧。1ページ12件で、横スワイプでページを送る(使うコントロールは要調査)
- 無料トライアル中は時計バッジ、解約済みはグレーアウト
- 並び順は「更新頻度順」と「登録順」。どちらでも解約済みは末尾
- 件数の表示(契約中 / うちトライアル / 解約済み)はデータから数える
- 0件のときは登録を促す案内と「サブスクを追加」ボタンを出す
- アイコンをタップすると詳細画面へ移る

## 5. APIとの連携

APIの仕様を決めるのはAPI担当です。この章は「アプリ側が必要としているもの」をまとめた依頼メモで、正式な仕様が出たらそちらに合わせて書き換えてください。

### アプリが必要とする機能

| 機能 | 使う画面 | `api_client.py` の関数(案) |
|---|---|---|
| 会員登録 | 会員登録・ログイン | `sign_up(email, password)` |
| ログイン、ログアウト | 会員登録・ログイン | `log_in(email, password)` / `log_out()` |
| 自分のサブスク一覧を取得 | ホーム、内訳、期限 | `list_subscriptions()` |
| サブスクを1件取得 | 詳細 | `get_subscription(sub_id)` |
| サブスクを登録 | 登録 | `create_subscription(data)` |
| サブスクを編集(解約・再契約の切り替えを含む) | 詳細 | `update_subscription(sub_id, data)` |
| サブスクを削除 | 詳細 | `delete_subscription(sub_id)` |
| 定番サービスを名称で検索 | 登録 | `search_services(keyword)` |
| 月の支払い見込み(総額、サービス別、前月差分) | 内訳 | `get_summary(month)` |

### アプリが必要とするサブスク1件のデータ

機能定義書(3)の項目に、状態を加えたものです。項目名は仮で、APIの正式な名前に合わせます。

| 項目 | 例 | 説明 |
|---|---|---|
| `id` | `3` | 一意なID |
| `name` | `"U-NEXT"` | サービス名 |
| `icon` | `"https://.../unext.png"` | アイコン画像のURL(なければ頭文字のタイルを表示) |
| `plan_name` | `"月額プラン"` | プラン名 |
| `cycle` | `"monthly"` | 更新周期。`monthly` / `yearly` |
| `amount` | `2189` | 1回の支払額(円) |
| `joined_at` | `"2026-09-20T21:00"` | 入会日時(分まで) |
| `join_url` | | 入会URL |
| `cancel_url` | | 退会(解約)URL |
| `cancel_memo` | | 退会に必要な情報のメモ |
| `status` | `"trial"` | `active`(契約中)/ `trial`(無料トライアル中)/ `cancelled`(解約済み) |
| `next_payment_at` | `"2026-10-20T21:00"` | 次回支払日時(APIが返す場合。7章を参照) |

各サービスのパスワードそのものは扱いません。機能定義書(6)のとおり、「退会手続き時にパスワードの準備が必要」という案内だけを表示します。

### アプリ側のルール

- APIの呼び出しは `api_client.py` にまとめ、各画面から直接 `httpx` を呼ばない
- `api_client.py` の関数は、`USE_DUMMY_DATA` が `True` の間は `dummy_data.py` の内容を返す。画面のコードはダミーか本物かを意識しない
- APIの項目名が変わっても画面を直さずに済むよう、項目名の変換は `api_client.py` の中で行う

## 7. 計算のルール

次回更新日と支払い見込みは、画面ごとに結果がずれないよう1か所だけで計算します。API側で計算するか、アプリ側で計算するかは未定です(要確認)。

- API側で計算する場合: アプリは返ってきた値を表示するだけにし、`src/logic/` は作らない
- アプリ側で計算する場合: `src/logic/` の関数だけを使い、各画面で同じ計算を書かない。`tests/` にテストを書く

どちらの場合も、計算の決まりは次のとおりにそろえます(API担当とも共有してください)。

### 次回更新日

- 入会日時と更新周期(月額 / 年額)から、現在より後で最も近い更新日を求める
- 月末のずれは「その月の末日に寄せる」(例: 1/31入会の月額 → 2/28、3/31、4/30)
- 解約済みは更新日なし
- 無料トライアル中は、トライアル終了日時を次回支払日として扱う(要確認)

### 支払い見込み

- 対象月に更新日が来るサブスクの金額を合計する(年額は更新月だけに全額を計上)
- 解約済みは含めない
- 前月差分は「当月の見込み − 前月の見込み」

年額を12で割って毎月に計上する方法もあります。どちらにするかは内訳画面の実装前に決めてください(要確認)。

## 8. デザインの共通ルール

色・フォント・余白は `src/theme.py` の定数を使い、画面ごとに色コードを直接書かないようにします。

| 定数 | 値 | 使いどころ |
|---|---|---|
| `GROUND` | `#F3F5F4` | 画面の地色 |
| `SURFACE` | `#FFFFFF` | ボタン、タブバー、カード |
| `INK` | `#14201C` | 本文 |
| `INK_SUB` | `#4A5552` | 補足テキスト |
| `LINE` | `#D3D8D6` | 枠線 |
| `ACCENT` | `#0E6B5C` | 主要ボタン、選択中の表示 |
| `TRIAL` | `#B45309` | 無料トライアルのバッジ |
| `OFF_FILL` / `OFF_INK` | `#D3D8D6` / `#5A6360` | 解約済みのグレーアウト |

- フォントは Zen Kaku Gothic New。フォントファイルを `assets/fonts/` に同梱する
- 左右の余白は24px、タップできる要素は44px以上
- 基準の画面幅は390px
- 状態の見せ方は全画面で統一する: 無料トライアル中は時計マーク、解約済みはグレーアウト。アイコン表示は必ず `components/service_icon.py` を使う

## 9. コーディング規約

- PEP 8 に従う。関数名・変数名は `snake_case`、クラス名は `PascalCase`
- 関数には1行でよいので説明コメント(docstring)を書く。コメントは日本語でよい
- 1画面 = 1ファイル。画面をまたいで使う部品は `components/` に置く
- 通信に失敗したとき、データが0件のときの表示も作る
- APIのURLやトークンなどをコードに直接書いてコミットしない(`config.py` で管理)
- Fletのバージョンを勝手に上げない(上げるときは全員で同時に)
- 担当者は一人１つのmd(docs/)をもち、設計した部分や他の開発者も知るべきことを書くようにする

## 10. Gitの進め方

- `main` には直接コミットしない。常に動く状態を保つ
- 作業ごとにブランチを作る: `feature/<画面や機能>`(例 `feature/detail-view`、`feature/sort-order`)
- コミットメッセージは日本語で「何をしたか」を1行で書く(例 `詳細画面: 次回支払日の表示を追加`)
- 作業を始める前に `main` を取り込む(`git pull origin main`)
- `.venv/`、`__pycache__/`、`build/` は `.gitignore` に入れる

## 11. テスト

```bash
pytest
```

- アプリ側で日付や金額を計算する場合、その関数はテスト必須
- 日付計算で最低限確認する場合: 月末入会(1/31、8/31)、うるう年の2/29、年額、年をまたぐ更新、解約済み、トライアル中
- 画面は、2nd スプリントで作るテスト計画(担当: 西内)に沿って、Androidの実機で手動確認する
- 結合テストでは、2台の端末で同じアカウントにログインし、登録内容が同期されることも確認する
