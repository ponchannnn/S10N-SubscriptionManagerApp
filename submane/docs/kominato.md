# 担当機能設計・開発メモ（小湊）

**担当機能**: 
- 詳細画面 (`src/views/detail.py`)
- 期限画面 (`src/views/deadline.py`)
- 日付計算ロジック (`src/logic/dates.py`)

---

## 1. 担当画面・モジュールの概要

### (1) 詳細画面 (`src/views/detail.py`)
登録されているサブスクリプションの詳細情報を表示し、契約内容の確認、退会ページの表示、解約/再契約状態の変更、削除を行う画面です。

- **次回更新日の表示**: `next_payment_at` がAPIから来ない場合は `logic/dates.py` で自動計算して表示します。
- **解約・退会URLへの遷移**: Flet の `page.launch_url()` を利用して外部ブラウザを開きます。
- **パスワード確認メモ**: 「退会手続きにはパスワード準備が必要」等の注意事項を表示します。
- **ステータス切り替え**: ボタン押下で `active` ⇔ `cancelled` を切り替え、`api_client.update_subscription` を呼び出します。
- **削除確認ダイアログ**: 誤操作防止のため確認ダイアログ（`AlertDialog`）を挟んでから削除を実行します。

### (2) 期限画面 (`src/views/deadline.py`)
支払期日（更新日）が近い順にサブスクリプションを一覧表示する画面です。

- **ソートルール**: `next_payment_at`（次回支払日）をもとに、本日からの残り日数が少ない順（昇順）で並べ替えます。
- **フィルタリング**: 解約済み（`status == "cancelled"`）のサービスは一覧から除外します。
- **ハイライト・バッジ表示**:
  - `本日更新`: 赤色バッジで強調
  - `あと 3 日以内`: オレンジ色バッジで注意喚起
  - `4日以上先`: 通常グレー表示

### (3) 日付計算ロジック (`src/logic/dates.py`)
他画面やAPIとの計算不一致を防ぐため、日付関連の計算を関数として共通化しました。

- `calculate_next_payment_date(joined_at_str, cycle, status)`:
  - 入会日・周期（`monthly` / `yearly`）・状態から次回支払日時を計算します。
  - **月末補正対応**: 1/31 入会の月額プランの場合、2月は 2/28（または 2/29）に寄せる調整を行います。
  - **無料トライアル**: `status == "trial"` の場合は、トライアル終了日（`joined_at`）を次回支払日として返します。
  - **解約済み**: `None` を返します。
- `get_days_until(target_date_str)`:
  - 対象日時と本日（`datetime.now().date()`）との日数差分を計算します。

## 3. 他の開発者（チームメンバー）への共有・注意事項

### API担当者へ
- **次回支払日の返却**: API側で `next_payment_at`（ISOフォーマット文字列）が返ってくる場合はそちらを優先表示します。返ってこない場合はアプリ側の `logic/dates.py` で計算します。
- **更新リクエスト**: 詳細画面での解約/再契約ボタンは `api_client.update_subscription(sub_id, {"status": new_status})` を発行します。

### ホーム画面担当（玉造さん）へ
- 詳細画面への遷移時は `sub_id`（サブスクID）をパラメータとして渡してください。
- 詳細画面から戻った際や、解約・削除が行われた後は、ホーム画面側で一覧データの再取得（`list_subscriptions`）を行ってください。

### テスト担当（西内さん）へ
- `src/logic/dates.py` の単体テストを `tests/test_dates.py` に作成予定です。
- 確認対象ケース：
  - 月末入会（1/31, 8/31）の翌月計算
  - うるう年（2/29）の計算
  - トライアル中の次回日付扱い
  - 解約済みの挙動
